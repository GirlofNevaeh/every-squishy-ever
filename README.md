# Every Squishy Ever

A mobile-first, kid-friendly catalog of squishy and sensory squeeze toys. Product data is a local JSON file. There is no database and no scraping.

## Add a squishy

The catalog is generated by [scripts/squishy-data.mjs](scripts/squishy-data.mjs). Run `node scripts/squishy-data.mjs` to rewrite [src/data/squishies.json](src/data/squishies.json). You can also paste one object by hand:

1. Copy an existing object and give it a new unique `id` (lowercase, hyphenated).
2. Fill in `name`, `brand`, `line`, `category`, `texture`, `size`, `colors`, `yearIntroduced`, `description`, `tags`, `amazonQuery`, `priceNote`, `imageKey`, `image`, `youtubeQuery`, and `bestsellerRank`.
3. `category` must be one of: NeeDoh, Cheese, Butter & Bread, Dumpling, Mochi & Candy, Fruit & Food, Animal, Cube & Stress, Mystery Box, Other.
4. `size` must be `mini`, `standard`, or `jumbo`.
5. `amazonQuery` is the Amazon search phrase (brand + product name). `amazonAsin` is optional. Set it only when you know the real Amazon product code, like `B0BQZFVJTB`. Leave it `null` to use a buy search instead. Do not invent a code.
6. `youtubeQuery` is a YouTube search phrase, usually the toy name plus “squishy”. Do not invent a video id.
7. `priceNote` is a rough range such as `often around $8–15` or `varies; check Amazon`. Never invent a live price.
8. `bestsellerRank` is `1`–`20` for the hall of fame, or `null`. Keep exactly twenty ranked toys.
9. `image` is `/squishies/{id}.jpg`. Photos in [public/squishies](public/squishies) are original catalog pictures, not scraped brand photos. If a file is missing, the card falls back to a simple drawing.
10. If the brand is an unofficial lookalike, set `brand` to `Generic` or the real maker. Do not call it NeeDoh unless Schylling made it.
11. Write an original, kid-friendly blurb. Do not paste manufacturer copy.

The suggest page can draft this object for you. It does not save anything by itself.

## Pages

- `/` search and filters, with a Top 20 chip and a show-more shelf.
- `/top` hall of fame. Not an official sales chart.
- `/squishy/$id` picture, feel, Amazon link, and YouTube search.
- `/play` a 20-question quiz. Play solo, or with up to 10 teams of 4 players (40 people). Each person gets a name, each team gets a name and a squishy icon, and the team shares one answer. A league table shows at the end.
- `/color` tap-to-fill coloring sheets you can print.

The footer button **Add to iPhone** or **Add to iPad** explains how to put the site on a home screen. **Save for offline** stores the pages and pictures on the device so the shelf still opens without wifi. Open the site in Safari first.

## Affiliate tag

Open [src/data/config.ts](src/data/config.ts). `AFFILIATE_TAG` defaults to `""`.

When it is empty, buy links are plain Amazon product pages or searches:

`https://www.amazon.com/s?k=YOUR+QUERY`

When you set a tag, links also include `&tag=YOUR_TAG`. No other environment variable is required for the site itself.

`SUGGEST_EMAIL` in the same file is optional. Leave it blank and the suggestion form still opens a mail draft.

## Photos

`scripts/generate-squishy-images.mjs` can fill missing JPEGs. It is a local helper, not part of `npm run build` or the public site. It needs `XAI_API_KEY` in the environment and writes 640×640 files to `public/squishies`. Do not commit an API key.

## Deploy on Vercel

The production build uses Nitro’s Vercel preset and writes the [Build Output API](https://vercel.com/docs/build-output-api) to `.vercel/output`. No environment variables are required. Do not add an API key.

1. Import this GitHub repo in Vercel.
2. Leave the framework as **Other** (already set in `vercel.json`).
3. Build command: `npm run build`. Do not set an Output Directory — Vercel picks up `.vercel/output`.
4. Deploy. Amazon and YouTube links stay search URLs. Photos ship with the app.

`npm run build` also runs the database migrator. With no `DATABASE_URL`, that step skips. This catalog does not need a database.
